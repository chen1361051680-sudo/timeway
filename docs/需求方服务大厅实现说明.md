# 需求方服务大厅实现说明

依据用户提供的两张需求方服务大厅参考图，实现于 `public/requester-hall.js`、`public/requester-hall.css`，通过现有 `/#services` 按身份展示。

## 页面与交互

- 天空城市页头、消息入口、圆角内容区、“已发布需求／待办”下划线标签、红色渐变按钮、服务图片、状态胶囊和固定四项导航按参考图实现。
- 已发布需求只提供“当前需求／历史记录”两个范围，默认查看当前需求。接口标记已结束或服务已确认完成的需求进入历史记录，按服务结束时间倒序展示；已取消需求仍不展示。“我的→帮扶记录”和已完成帮扶统计进入历史记录。分类只影响展示，不修改服务状态、时长或业务数据。
- 当前需求按服务阶段和开始时间排列，刚发布的需求优先显示。历史任务的待核实、异议、退出与安排变更仍由全量数据生成待办，不因归入历史记录而丢失提醒；暂停、结束与异常显示实际状态，不误判为已完成。
- 卡片展示公开区域、上海时区预约时间、时长、已确认人数。处理报名、查看安排、确认服务和查看记录跳到共用详情对应区域。
- 待办按待处理报名、待确认服务、其他事项分组，统计待处理人数／事项数。点击统计可筛选，再次点击恢复全部。
- 同一需求存在不同种类的待办时分别展示；截图中的 3、17、8、6 等数字由实际 SQLite 数据替代，不写死。
- 详情返回保留标签、筛选与滚动位置。处理后重新读取列表；消息红点来自真实未读状态。
- 页面沿用站内 MiSans Normal 400、Semibold 600；窄屏和大字模式适配。手机系统状态栏与底部系统手势条由设备显示，不作为网页模拟内容。

## 帮扶需求详情

- 详情沿用两种角色共用页面，以需求概览、服务安排、服务内容、报名与服务四层展示，使用独立的 `task-detail.js` 与 `task-detail.css`。
- 概览突出标题、实际状态、时长、需要人数和已确认人数；时间、地点、联系人分行展示，报名截止作为辅助信息保留。地址仍遵守接口权限，未确认参与者只能查看公开区域。
- 待处理报名、服务核实、异议和安排变更按实际数据提示，点击直接定位。人员列表优先展示待处理事项，保留原有确认、核实、退出和调整流程。
- 删除未填写的要求占位、默认套话、受助对象及集合说明展示；不重复列出地点、机构或额外的大块空状态。不删除已有业务记录。
- 底部固定“更多／编辑内容／当前主要操作”，暂停、开放发布、取消、变更记录和成果地点更正集中到“更多”。“留言与评价”“服务材料”功能已移除，清理相关入口、弹窗、样式及接口；保留服务记录、核实与历史数据。
- `npm run test:task-detail` 验证四种宽度、大字与长文本、状态刷新、待办定位、报名确认、编辑跳转、暂停恢复及取消确认保护；隔离测试截图位于 `tmp/ui-checks/task-detail-*.png`。

## 其他事项的处理

- 已移除志愿者“申请调整时间”功能，包括申请弹窗、需求方审批、待办计数及对应接口操作；旧申请不再生成处理入口。历史数据与审计记录保留。
- 需求方编辑需求导致服务安排变更时，仍沿用原有参与者确认机制，所有相关志愿者完成确认后新安排生效。
- 已确认志愿者退出产生待办；需求方记录联系、补招或调整安排的处理结果后移出待办，保留退出与处理记录。
- 异议跳转服务记录核实区。所有写入使用现有权限、CSRF、事务与幂等请求机制，业务处理留审计记录。安排变更和退出处理不产生志愿时间或地图成果。
- 数据保存在现有 SQLite JSON 实体，无结构迁移，不初始化或替换用户业务数据。

## 素材

- `public/images/requester-hall-reference.png`：用户提供的第一张参考图原文件，只通过 CSS 背景位置显示其中的四张服务类型配图。所有文字、按钮、数字与布局均为真实 HTML，不用整页截图充当界面。配图仅为服务类型示意。
- `public/images/requester-hall-header.png`：内置 imagegen 编辑模式根据参考图生成的无文字天空城市背景，已复制进项目静态资源；没有使用 CLI。
- 构建自动包含新增 JS、CSS、图片和原有 MiSans 字体。
