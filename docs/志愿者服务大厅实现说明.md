# 志愿者服务大厅实现说明

依据：用户提供的服务大厅截图、时光有路-功能需求文档.md、时光有路-UI页面功能说明.md。

## 页面与数据

- 入口：志愿者登录后，底部“服务大厅”，路由 /#services。
- 样式：手机优先，最大宽度 470px；天空城市与爱心插画、文字下划线标签、浅蓝搜索与五项筛选、圆角图文卡片、珊瑚红按钮、固定四项导航。
- 全站使用站内 MiSans Normal（400）和 Semibold（600），静态服务器与构建均包含字体与页面素材。
- 搜索服务、机构和区域；筛选类型、区域、距离、日期、有效时长、含往返的可用时间；按距离或开始时间排序。
- 我参与的显示当前账号实际任务、待跟进数量与状态，支持待处理、进行中、已完成、其他、日期与机构筛选。
- 卡片进入共用任务详情；报名后更新列表与数量，返回恢复筛选和滚动位置。
- 发现列表排除已截止、已满额、取消和变更中的任务；本人历史记录保留。
- 地图跳转列表时分别传递区域与关键词，避免组合成无法匹配的单一关键词。
- 通知红点来自真实未读数，全部已读后同步移除。

## 数据真实性

当前百度地图路线适配仍未接通，实际页面显示“到达时间待确认”，不填写设计图中的假距离；选择距离或往返预算后，未知路线不会当作零。距离优先时，距离未知的任务按开始时间排在已知距离之后。

服务类型图片为 AI 生成示意素材，并非某一次真实服务的照片。设计图中的固定日期、机构、人数与参与数字不硬编码进业务页。视觉样例仅存在于独立 test 内存数据库，未修改开发或生产业务数据库。

## 验证

- npm test：17 项业务、权限、数据隔离与服务大厅排序/招募过滤测试。
- npm run test:hall：320、390、470、1440 像素视口；搜索、筛选、取消与重置、空状态、参与状态、报名更新、详情返回、未知/已知路线、隐私和资源加载。
- npm run test:ui：两角色业务全链路回归。
- npm run build：构建包含 hall.js、hall.css、字体与 5 张服务大厅插画。
- 截图：tmp/ui-checks/hall-390.png、hall-470.png、hall-mine.png、hall-empty.png。hall-route-fixture.png 的路线仅为测试适配数据。
